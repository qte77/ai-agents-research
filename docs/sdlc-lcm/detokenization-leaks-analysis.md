## What It Is

An arXiv paper, "Detokenization Leaks: Reconstructing Local LLM Outputs From Cache
Traces" (arXiv:2609.06674v1, submitted 2026-09-06, cs.CR / cs.AI; authors Roy Weiss,
Benyamin Konstantinov, Eitam Sheetrit, Tomer Simon, Yisroel Mirsky), demonstrating that
an attacker with access to CPU cache-timing side channels — **Flush+Reload** and
**Prime+Probe** — can reconstruct text generated by a **locally hosted** LLM without
reading memory or network traffic. The attack targets the **detokenization** step: cache
timing reveals *when* decoding happens and isolates token-dependent cache patterns,
which are then denoised via clustering and a language model to recover the underlying
text. Evaluated across multiple datasets, hardware platforms, and model families.

## Scope: what it attacks, and what it does not

The attack requires the attacker to share a physical machine (or a co-tenant VM with
cache access) with the process running LLM inference — it is a side channel on the
**inference host**, not on network traffic or on a remote API. The paper's own
evaluation targets are **OpenClaw, Llama-3, and Phi-3-mini** — locally-run, open-weight
model deployments.

**Claude Code is named once, and is not evaluated.** The introduction lists it as an
example of the kind of agent framework this threat matters for: "Frameworks such as
OpenClaw and Claude-Code enable agents to perform tasks including file management,
coding, and personal assistance, often operating on sensitive inputs such as local
files, credentials, and private communications." That is a namecheck to motivate why
local-inference confidentiality matters for coding-agent workloads generally — it is
**not** a claim that Claude Code's own inference (which runs on Anthropic's hosted API,
not on the user's local hardware) is vulnerable to this specific attack. The attack
surface described here applies to *self-hosted, local-weight* agent deployments; it does
not transfer to a hosted-API client without a locally-run model in the loop.
